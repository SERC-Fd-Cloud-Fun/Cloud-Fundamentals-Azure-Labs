# Lab 4: Web and Database Servers on a Virtual Machines

In this lab, you will learn how to set up a web server and a database server on virtual machines in Azure. You will install the necessary software and configure the servers to serve a simple web page and manage a database.

## Learning objectives

By the end of this lab, you should be able to:
- Create Linux virtual machines from the Azure portal
- Configure inbound networking rules for VM access
- Connect to VMs using SSH public key authentication
- Install and validate Apache, PHP, and MariaDB on Ubuntu
- Deploy a PHP page that reports VM details and database connectivity
- Update reverse DNS using a provided HTTP endpoint

## Prerequisites

- Access to an Azure subscription provided for the course (`Cloud Fundamentals Labs`) and resource group (`CloudFun-Lab04-WebServer-<your studentid number>`)
- A subdomain for reverse DNS configuration (provided by your instructor)
- Azure portal access: https://portal.azure.com
- A terminal application for SSH

## Naming and resource guidance

- Place all resources in the assigned subscription and resource group (or create one if your instructor asks you to)
- Use consistent names such as:
  - `lab4-web-vm`
  - `lab4-db-vm`
  - matching virtual networks/NICs/public IP names generated by Azure
- Choose a region close to your location unless your instructor specifies one

## Exercise 1 - Create and configure the web server VM

### 1. Create the VM

1. In the Azure portal, navigate to "Virtual machines" and click "Create" > "Virtual machine".
2. Fill in the basic details:
    - Subscription: `Cloud Fundamentals Labs`
    - Resource group: `CloudFun-Lab04-WebServer-<your studentid number>`
    - Virtual machine name: `lab4-web-vm`
    - Region: Choose a nearby region
    - Image: Ubuntu Server 24.04 LTS
    - Size: Select a size (e.g., **Standard_B1s** for testing)
    - Authentication type: **SSH public key**
    - Username: `azureuser`
    - SSH public key: **Generate a new key pair**
    - Inbound ports: allow:
        - SSH (22)
        - HTTP (80)
        - HTTPS (443)
3. Click "Review + create" and then "Create" to deploy the VM.
4. Download the SSH private key when prompted, and save it securely for later use.

### 2. Connect to the VM

1. Once the VM is deployed, go to the "Overview" page of `lab4-web-vm`.
2. Note the public IP address assigned to the VM.
3. Open a terminal and connect to the VM using SSH:
   ```bash
   ssh -i /path/to/your/private/key azureuser@<public-ip-address>
   ```

### 3. Install Apache and PHP

Run the following on the web VM:

```bash
sudo apt update
sudo apt install -y apache2 php libapache2-mod-php php-mysql
```

### 4. Validate Apache is working

1. Ensure the service is active:

```bash
sudo systemctl status apache2
```

2. In a browser, open `http://<web-vm-public-ip>`.
3. Confirm the default Apache page loads before continuing.

### 5. Create and run reverse DNS update script

The public IP address of the VM is dynamic and may change on restart. For a stable address we will use a dynamic DNS service. Dynamic DNS services allow you to associate a domain name with a changing IP address.

You will use the provided HTTP endpoint to update the reverse DNS record for your VM's public IP address. This will allow you to access your VM using a domain name instead of the IP address.

You have been provided with a subdomain at `<your studentid number>.cloud-it.cloud` for this purpose.

1. Create a script to update the reverse DNS record:

```bash
nano update_dns.sh
```

2. Add the following content to the script, replacing `<your studentid number>` with your actual student ID and `<your-update-token>` with a string of your choice (this token is used to authenticate your updates):

```bash
#!/bin/bash
# Use your assigned student/team subdomain value.
SUBDOMAIN="<your-subdomain>"
UPDATE_TOKEN="<your-update-token>"

# Use the provided HTTP endpoint to update the reverse DNS record
curl -sf "https://func.cloud-it.cloud/api/UpdateDNS?code=${FUNCTION_SECRET}&token=${UPDATE_TOKEN}&subdomain=${SUBDOMAIN}"
```

3. Make the script executable:

```bash
chmod +x update_dns.sh
```

4. The update endpoint also requires a secret for authentication. You will need to obtain this secret from your instructor or the course materials. We will use a system environment variable to store this secret securely. Set the environment variable in your shell:

```bash
export FUNCTION_SECRET="<function-secret>"
```

5. Run the script to update the reverse DNS record:

```bash
./update_dns.sh
```

6. After running the script, you should be able to access your VM using the subdomain you configured (e.g., `http://<your-subdomain>.cloud-it.cloud`). Test this in your browser to confirm it resolves to your VM's public IP address and shows the Apache default page.

7. To ensure the reverse DNS record is updated automatically after a reboot (since the public IP may change), you can add the script to your crontab. Open the crontab editor:

```bash
crontab -e
```

> cron is a time-based job scheduler in Unix-like operating systems. It allows you to schedule scripts or commands to run at specific intervals or events, such as system reboot.

Add the following line to the end of the crontab file to run the update script at every reboot: (replace `/path/to/update_dns.sh` with the actual path to your script)

```bash
@reboot /path/to/update_dns.sh
```

This will ensure that the reverse DNS record is updated automatically whenever the VM restarts, keeping your subdomain pointing to the correct IP address.

### 6. Create a PHP page to display VM details

1. Create a new PHP file in the Apache web root directory:

```bash
sudo nano /var/www/html/info.php
```

2. Add the following content to the `info.php` file:

```php
<?php
echo "<h1>VM Information</h1>";
echo "<p>Hostname: " . gethostname() . "</p>";
echo "<p>IP Address: " . $_SERVER['SERVER_ADDR'] . "</p>";
?>
```

3. Save and exit the file.

4. In a browser, navigate to `http://<your-subdomain>.cloud-it.cloud/info.php` (or `http://<web-vm-public-ip>/info.php` if you haven't set up the subdomain). You should see a page displaying the hostname and IP address of your VM. This confirms that your web server is correctly serving PHP content and that the reverse DNS configuration is working as expected.

### 7. Secure with Let's Encrypt SSL (Single VM Setup)

To secure your web server with HTTPS, you can use Let's Encrypt to obtain a free SSL certificate. Follow these steps to set up SSL on your single VM:

1. Install Certbot, the Let's Encrypt client:

```bash
sudo apt install -y certbot python3-certbot-apache
```

2. Obtain and install the SSL certificate for your subdomain:

```bash
sudo certbot --apache -d <your-subdomain>.cloud-it.cloud
```

(Make sure to replace `<your-subdomain>` with the actual subdomain you are using for your VM.)

3. Follow the prompts to complete the certificate installation. Certbot will automatically configure Apache to use the new SSL certificate.

4. After the installation is complete, you can access your web server securely using `https://<your-subdomain>.cloud-it.cloud`. You should see a secure connection indicator in your browser, confirming that SSL is properly configured.

5. To ensure that your SSL certificate is renewed automatically, Certbot sets up a cron job by default. You can verify this by checking the contents of the `/etc/cron.d/certbot` file:

```bash
cat /etc/cron.d/certbot
```

This file should contain a scheduled task that runs the Certbot renewal command periodically, ensuring that your SSL certificate remains valid without manual intervention.

## Exercise 2 - Create and configure the database server VM

We will create a second VM to host the database server. This separation allows for better security and performance. We will setup this VM so that it can only be accessed from the web server VM, and not directly from the internet.

### 1. Create ssh key pair for database VM

1. On the web VM, generate a new SSH key pair for the database VM:

```bash
ssh-keygen -t rsa -b 2048 -f ~/.ssh/lab4-db-key
```

2. This will create two files: `lab4-db-key` (private key) and `lab4-db-key.pub` (public key). You will use the public key when creating the database VM and keep the private key secure for SSH access.

3. Copy the public key to your local machine for use in the Azure portal:

```bash
cat ~/.ssh/lab4-db-key.pub
```

### 3. Create the database VM

1. In the Azure portal, navigate to "Virtual machines" and click "Create" > "Virtual machine".

2. Fill in the basic details:
    - Subscription: `Cloud Fundamentals Labs`
    - Resource group: `CloudFun-Lab04-WebServer-<your studentid number>`
    - Virtual machine name: `lab4-db-vm`
    - Region: Choose the same region as the web VM
    - Image: Ubuntu Server 24.04 LTS
    - Size: Select a size (e.g., **Standard_B1s** for testing)
    - Authentication type: **SSH public key**
    - Username: `azureuser`
    - SSH public key: **Use existing public key**
      - Paste the contents of `lab4-db-key.pub` that you generated on the web VM (beginning with `ssh-rsa` and ending with your username. becareful to copy the entire key without any extra spaces or newlines.)
    - Inbound ports: allow only SSH (22)

3. On the "Networking" tab
    - Virtaul network: Select the same virtual network as the web VM
    - Subnet: default (or the same subnet as the web VM)
    - Public IP: None (we will not assign a public IP to the database VM for security reasons)
    - Select inbound ports: SSH (22) only
    - Load balancing: None
    - Click "Review + create" and then "Create" to deploy the VM.

### 4. Configure network security group (NSG) rules

We need to configure the NSG rules to allow the web VM to communicate with the database VM on the necessary ports (e.g., MySQL default port 3306) while blocking all other inbound traffic to the database VM.

1. After the database VM is deployed, navigate to the "Networking" section of the `lab4-db-vm` in the Azure portal.

2. Click on the NSG associated with the database VM (it should be listed under "Network security group").

3. Update the existing SSH rule to allow access only from the web VM:
    - Click on the SSH rule (allowing port 22) and edit it:
        - Source: **IP Addresses**
        - Source IP addresses/CIDR ranges: Enter the private IP address of the web VM (you can find this in the "Networking" section of the web VM)
        - Source port ranges: *
        - Destination: **Any**
        - Service: **SSH**
        - Action: **Allow**
        - Priority: Set a priority (e.g., 300)

3. In the NSG settings, click "Create port rule" and select "Inbound port rule"to create a new rule.
    - Source: **IP Addresses**
    - Source IP addresses/CIDR ranges: Enter the subnet range of your virtual network (e.g., `10.0.0.0/24`)
    - Source port ranges: *
    - Destination: **Any**
    - Service: **MySQL**
    - Action: **Allow**
    - Priority: Set a priority (e.g., 310)
    - Name: `Allow-MySQL-From-WebVM`

### 5. Connect to the database VM from the web VM

1. From the web VM, use SSH to connect to the database VM using the private key you generated:

```bash
ssh -i ~/.ssh/lab4-db-key azureuser@<database-vm-private-ip>
```

(You can find the private IP address of the database VM in the "Networking" section of the database VM in the Azure portal.)

### 6. Install MariaDB on the database VM

1. Once connected to the database VM, update the package lists and install MariaDB:

```bash
sudo apt update
sudo apt install -y mariadb-server
```

2. Start the MariaDB service and enable it to start on boot:

```bash
sudo systemctl start mariadb
sudo systemctl enable mariadb
```

3. Secure the MariaDB installation by running the security script:

```bash
sudo mysql_secure_installation
```

Follow the prompts to set a root password and secure your MariaDB installation.

### 7. Allow remote connections to MariaDB

1. Edit the MariaDB configuration file to allow remote connections:

```bash
sudo nano /etc/mysql/mariadb.conf.d/50-server.cnf
```

2. Find the line that starts with `bind-address` and change it to:

```ini
bind-address = 0.0.0.0
```

This will allow MariaDB to listen for connections on all network interfaces.

3. Save and exit the file.

4. Restart the MariaDB service to apply the changes:

```bash
sudo systemctl restart mariadb
```

### 8. Create a database and user for the web application

1. Log in to the MariaDB shell:

```bash
sudo mysql -u root -p
```

2. Create a new database for the web application:

```sql
CREATE DATABASE webapp_db;
```

3. Create a new user and grant them permissions on the database:

```sql
CREATE USER 'webapp_user'@'10.0.0.%' IDENTIFIED BY 'your_secure_password';
GRANT ALL PRIVILEGES ON webapp_db.* TO 'webapp_user'@'10.0.0.%';
FLUSH PRIVILEGES;
```

Replace `your_secure_password` with a strong password of your choice.

4. Exit the MariaDB shell:

```sql
EXIT;
```

### 9. Update the PHP page to connect to the database

1. On the web VM, edit the `info.php` file to include database connection details:

```bash
sudo nano /var/www/html/info.php
```

2. Update the content of `info.php` to include the following code, which will attempt to connect to the MariaDB database and display a success message if the connection is successful:

```php
<?php
echo "<h1>VM Information</h1>";
echo "<p>Hostname: " . gethostname() . "</p>";
echo "<p>IP Address: " . $_SERVER['SERVER_ADDR'] . "</p>";

// Database connection details
$servername = "lab4-db-vm";
$username = "webapp_user";
$password = "your_secure_password";
$dbname = "webapp_db";

echo "<h2>Database Connection Test</h2>";

// Create connection
$conn = new mysqli($servername, $username, $password, $dbname);
// Check connection
if ($conn->connect_error) {
    echo "<p>Failed to connect to the database: " . $conn->connect_error . "</p>";
    die("Connection failed: " . $conn->connect_error);
} else {
    echo "<p>Successfully connected to the database!</p>";
}
$conn->close();
?>
```

Make sure to replace `your_secure_password` with the password you set for the `webapp_user`. The `$servername` should match the hostname or private IP address of the database VM (hostname will be resolved if the VM is in the same virtual network).

3. Save and exit the file.

4. In a browser, navigate to `http://<your-subdomain>.cloud-it.cloud/info.php` (or `http://<web-vm-public-ip>/info.php`). You should see a message confirming that the connection to the database was successful, indicating that your web server can communicate with the database server as intended.
